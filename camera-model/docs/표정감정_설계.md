# 카메라 기반 감정/표정 분석 모듈 — 진행 메모

담당: 김도현 (카메라 관련 모델 개발)

## 요구사항
1. 카메라로 환자 표정 분석, 감정 상태 분류
2. 최근 일정 기간 감정 변화 비율 기록 → 정서 변화 추이 확인
3. AI Hub 감정 분류 데이터셋 검토

## 분류 카테고리 결정

최종 출력은 **통증 / 불안 / 무기력 / 평온(baseline)** 4종으로 잡는다(기획서 타겟과 일치).
사전학습 FER 7종(분노/혐오/공포/행복/슬픔/놀람/중립)은 학습 없이 바로 쓸 수 있는
"중간 신호"로 두고, 아래처럼 프록시 매핑해서 4종으로 환원한다.

| 최종 카테고리 | FER 원시 신호 조합 (프록시) |
|---|---|
| 통증 | 분노 + 혐오 (미간 찌푸림 등 AU 유사성 근거) |
| 불안 | 공포 + 놀람 |
| 무기력 | 슬픔 + 중립 |
| 평온 | 행복 + (전체적으로 낮은 각성도) |

## 한계 / 예외 케이스 (반드시 교차검증과 함께 써야 하는 이유)

1. **파킨슨 환자 — 가면양 얼굴(hypomimia)**: 시나리오3(사토 켄지)처럼 파킨슨병 환자는
   질환 자체가 표정 변화를 둔화시켜서, 실제로는 통증/불안을 느껴도 표정에 잘 안 드러날 수 있음.
2. **일본 문화권 — 표현 억제(display rule)**: 심리학 연구(Ekman의 cross-cultural display
   rule 연구 등)에 따르면 일본 문화권은 특히 부정적 감정(분노, 혐오, 슬픔 등)을 타인 앞에서
   표정으로 잘 드러내지 않는 경향이 보고됨. 페르소나 3명 중 2명(다나카 하루코, 사토 켄지)이
   일본인이라 이 프로젝트에 실질적으로 영향을 줄 수 있는 문제.
3. **사전학습 데이터셋 편향**: FER2013 등은 서구권 얼굴 위주라 동아시아 얼굴 전반에 대한
   기본 정확도 자체가 낮을 수 있음(한국인/일본인 공통 문제).

→ 대응: "표정 변화가 거의 없음" 자체를 하나의 관찰 신호(저활성 표정 플래그)로 다루고,
이 플래그가 뜨면 표정 결과 단독으로 판단하지 않고 챗봇 대화(S 정보)·생체신호(O 정보)와
반드시 함께 교차검증하도록 설계한다(기획서의 "3종 데이터 교차 제시"와 일치).

## 진행 상태 업데이트 (2026-09-22)

FER2013 기반 사전학습 모델로 실측 테스트 결과, 조명이 어두운 환경에서 웃는 얼굴도
sad/neutral로 오분류되는 문제를 확인함. 프레임 밝기를 함께 로깅하도록 코드를 보강해
"모델 자체 한계"와 "조명 문제"를 구분할 수 있게 했으나, 현재 이 모델은 그대로
채택하기 어렵다고 판단하여 보류 중. 다음 논의 필요:
- 조명을 개선한 재테스트로 원인 재확인
- 랜드마크 기반(MediaPipe FaceMesh + 규칙) 방식으로 전환 검토

## 랜드마크 기반(v1) 착수 (2026-09-22)

FER 모델 보류 결정에 따라 MediaPipe FaceMesh 기반 규칙 방식(`landmark_expression_tracker.py`)
착수. "표정 변화가 있는지 없는지"를 가장 먼저 정량화(`expression_activity`)하고, 그 위에
통증/불안/무기력/평온 프록시를 규칙으로 얹는 구조 — 파킨슨/문화적 표현 억제로 인한
저활성 표정을 감지하려는 원래 목적과 직접 연결됨. 세부 지표/규칙 설명은
`face-emotion/README.md` 참고.

## 규칙 v2 (2026-09-28)

9/23 라벨 테스트(v1)에서 frown이 pain으로 거의 안 잡혔다(pain 0.005~0.05, 오히려 lethargy가 더 높음).
표정별 delta를 뜯어보니 가중치보다 **지표 정의 자체**가 문제였다.

| 문제 (v1 로그 근거) | 원인 | v2 수정 |
|---|---|---|
| frown에서 `brow_gap`/`brow_raise` 변화가 median ±0.005 수준 | `brow_raise` = 눈썹~윗눈꺼풀 거리라서, 찡그릴 때 눈꺼풀도 같이 내려오면 상쇄 | `brow_height` = 눈 안쪽 모서리선 기준 눈썹 높이 (눈꺼풀과 분리) |
| droopy가 anxiety 0.175로 오판 | 눈꺼풀이 처지면 눈썹~눈꺼풀 거리가 커져 `brow_raise` 가중치를 탐 | 위와 동일 |
| `corner_y` 기준선이 실행마다 3.00~3.56, neutral도 +0.07 drift | 입꼬리의 화면 절대 y좌표라 고개만 움직여도 변함 | `corner_lift` = 입 중앙 대비 입꼬리 높이 |
| 찡그림의 입 주변 신호가 없음 | — | `nose_lip`(코밑~윗입술, AU9/10) 추가 |
| 고개 기울기/화면 비율 영향 | 높이를 화면 y축으로, x·y 단위가 다른 정규화 좌표로 계산 | 눈 축에 수직 방향으로 높이 측정 + x에 화면 비율 곱함 |
| 평균 delta로 프록시 1회 계산 → 여러 표정이 섞이면 상쇄 | — | 프레임별 프록시 평균 + `dominant_ratio`(상태별 비율) |

프록시는 PSPI(= AU4 + max(AU6,AU7) + max(AU9,AU10) + AU43)를 근사한다. 단, 눈 가늘어짐만 있고
찡그림(AU4, AU9/10)이 없으면 졸림/무기력 쪽으로 보내서 pain과 lethargy를 구분한다.
각 delta는 구간(`RULE_RANGES`)으로 0~1 점수화하고, 하한값 아래는 노이즈로 무시한다.

**검증 상태**: 합성 랜드마크 테스트에서 5개 라벨 모두 의도대로 판정되고, 고개 이동/기울기에
지표가 변하지 않는 것은 확인했다. 하지만 v1 로그는 좌표가 없어 v2로 재채점할 수 없으므로,
**실제 얼굴 정확도는 재녹화 후 확인 필요**. v2부터는 `key_landmarks`가 저장되니
이후 튜닝은 `evaluate_runs.py`로 재녹화 없이 반복 가능.

## 규칙 v2.1 (2026-09-29)

v2로 재녹화한 결과(전체 49.7%) frown→pain은 85%로 잘 잡혔지만, smile과 droopy도 pain으로 판정됐다.
프레임별 `actions`를 보니:

| 문제 | 원인 | 수정 |
|---|---|---|
| smile → pain (정답 9%) | 진짜 웃음(뒤센 미소)은 눈이 가늘어지고 눈썹도 내려와서 찡그림처럼 보임 (`brow_lower` 1.0) | 입꼬리 웃음 점수만큼 찡그림을 깎음 |
| smile/droopy 모두 `lip_raise` 1.0 | 입을 옆으로 늘리기만 해도 윗입술 안쪽 점이 움직여 코밑~윗입술 거리가 줄어듦 → AU9/10 신호로 못 씀 | 찡그림 판정에서 제외 (기록은 유지) |
| droopy → pain (정답 0%) | 위와 같음 + 입이 옆으로 벌어져 smile 점수도 오름 | 웃음은 입꼬리가 올라갈 때만 인정, 입꼬리 처짐의 무기력 가중치 상향 |

| label | v2 | v2.1 |
|---|---|---|
| neutral | 90% | 90% |
| frown | 85% | 72% |
| smile | 9% | 93% |
| wide_eyes | 57% | 57% |
| droopy | 0% | 69% |
| **전체** | **49.7%** | **77.7%** |

남은 오답 대부분은 모든 동작 점수가 0인 프레임(녹화 중 표정을 잠깐 풀었던 구간)이라 규칙 문제는 아니다.
droopy→pain 오답 일부는 실제로 미간을 모은(`brow_squeeze` 0.7) 프레임이라, 한 사람 데이터에 맞춰
더 조정하지 않고 다른 사람 데이터로 확인한 뒤 결정한다.
