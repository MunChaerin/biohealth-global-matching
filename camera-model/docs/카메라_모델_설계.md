# 카메라 관련 모델 개발 설계 문서

**프로젝트**: 2조 스바라시2 — 바이오헬스 글로벌 매칭 프로그램
**범위**: 표정 분석(정서·통증), 자세 변화/낙상 감지, 복용 약 알약 인식
**현재 단계**: 9월 2~4주차 "카메라 모델 설계" 구간 (프로토타입은 출국 전 목표)

---

## 1. 전체 아키텍처

침상 옆 고정 카메라(웹캠 또는 스마트폰 거치) 하나로 세 기능을 모두 처리하되, 상시 구동이 필요한 기능과 이벤트 트리거로만 구동되는 기능을 분리해서 자원을 아낀다.

```
[카메라 입력]
     │
     ├─ 상시 파이프라인 (낮은 fps, 예: 1~3fps)
     │     ├─ 자세/낙상 감지 모듈
     │     └─ 표정·정서 분석 모듈 (주기적 샘플링, 예: 30초~1분 간격)
     │
     └─ 이벤트 트리거 파이프라인 (복약 알림 시각에만 활성화)
           └─ 알약 인식 모듈

     각 모듈 출력
           │
           ▼
   [통합 이벤트 스키마] → FastAPI 백엔드 → DB 저장
           │
           ├─ 의료진 대시보드 알림 (낙상/장시간 자세/오복용 의심 등 긴급 이벤트)
           └─ SOAP 리포트의 'O(Objective)' 항목 데이터로 챗봇의 S 데이터와 함께 종합
```

핵심 설계 원칙:
- **경량 상시 처리 + 무거운 모델은 트리거 시에만** — 침상 카메라가 24시간 도는 만큼 상시 구동 모델은 최대한 가볍게(포즈 추정 등), 알약 인식처럼 정밀도가 필요한 모델은 알림 시점에만 호출한다.
- **판단 근거를 함께 로깅** — 기획서의 차별화 포인트("AI 평가에 상세한 근거 제공")에 맞춰, 각 모듈은 confidence score와 판단에 쓰인 keypoint/landmark 값을 이벤트에 함께 저장한다.
- **엣지 우선, 프라이버시 고려** — 환자 얼굴 원본 영상은 서버로 전송하지 않고, 로컬(엣지)에서 특징값만 추출해 전송하는 구조를 지향한다(요양원 특성상 영상 데이터 저장/전송 자체가 민감 이슈가 될 수 있음).

## 2. 모듈별 설계

### 2.1 자세 변화 / 낙상 감지 — 우선 구현 대상 ①

**목표**: 장시간 동일 자세 유지 감지(욕창 예방) + 낙상 감지(응급 알림)

- **모델**: 커스텀 학습 없이 시작 가능한 사전학습 포즈 추정기 사용
  - MediaPipe Pose 또는 YOLOv8-pose → 실시간 33개(또는 17개) keypoint 추출
  - 별도 학습 데이터 없이도 데모가 가능해 가장 먼저 프로토타입화하기 좋음
- **로직**:
  - *동일 자세 유지*: keypoint 좌표의 프레임 간 변화량을 누적 → 일정 임계값 이하 변화가 N분 이상 지속되면 "체위 변경 알림" 이벤트 발생
  - *낙상 감지*: 몸통(어깨-엉덩이) 각도가 급격히 수평에 가까워지거나, 무게중심(엉덩이 keypoint)의 y좌표가 짧은 시간에 급락하면 낙상 후보로 판정 → 오탐 줄이기 위해 낙상 후 일정 시간 움직임 없음(무반응)까지 확인 후 확정
- **참고 데이터셋**: UR Fall Detection Dataset, Le2i Fall Detection Dataset (임계값 튜닝/검증용)
- **확장 아이디어(기획서 b항목)**: 뇌파(EEG)·EMG 기반 "운동 의지 vs 실제 모션" 비교는 이번 로컬 프로토타입 범위를 넘는 하드웨어 연동이 필요 — 1차 프로토타입에서는 카메라 기반 자세 로직까지만 구현하고, 뇌파 비교는 사업화 로드맵 상 확장 기능으로 문서화 권장

### 2.2 표정 분석 (통증/불안/무기력)

**목표**: 단순 6종 감정 분류가 아니라 "통증·불안·무기력" 같은 임상적으로 의미 있는 상태 변화 포착

- **1단계(랜드마크 기반, 가벼움)**: MediaPipe FaceMesh로 얼굴 랜드마크 추출 → 눈썹 하강, 눈 찡그림, 입가 처짐 등 Action Unit 유사 특징을 규칙 기반 또는 소형 분류기(SVM/MLP)로 판정
  - 통증 판정의 임상 표준으로 **PSPI(Prkachin and Solomon Pain Intensity)** 스케일을 참고하면 "정서 분류"보다 근거를 대기 쉬움
- **2단계(데이터 확보 시)**: UNBC-McMaster Shoulder Pain Expression Archive Database로 파인튜닝한 CNN 기반 통증 강도 회귀 모델
- **주의**: 실제 환자 얼굴 데이터 수집은 시간이 걸리므로, 로컬 프로토타입 단계에서는 1단계(랜드마크+규칙 기반)로 데모하고, 정확도 고도화는 귀국 후 과제로 남기는 것을 추천
- **출력**: pain/anxiety/lethargy 각각의 score(0~1) + 근거 landmark 특징값 → SOAP의 O 데이터로 전달

### 2.3 복용 약 알약 인식

**목표**: 복약 알림 시각에 카메라 활성화 → 환자가 보여준 약과 등록된 처방 정보 비교

- **모델**: YOLO 계열 커스텀 파인튜닝 (알약 검출 + 형태/색상 분류)
  - 1단계: 알약 영역 검출(bounding box)
  - 2단계: 색상(HSV 히스토그램) + 모양(원/타원/캡슐 등, contour 기반) + 각인 텍스트(선택적 OCR) 특징 추출
  - 등록된 복약 DB(의료진이 사전 입력한 시간·종류·외형 정보)와 매칭해 "일치/불일치" 판정
- **데이터셋**: 자체 촬영 데이터가 가장 정확하지만, 초기 프로토타입은 NIH Pill Image Recognition Dataset(공개) 일부로 형태/색상 분류기를 사전학습 후 소량의 자체 데이터로 파인튜닝하는 방식을 권장
- **트리거 구조**: 알림 시점에만 카메라를 활성화하므로 상시 파이프라인과 분리 — FastAPI 엔드포인트로 "복약 인식 요청"을 받아 단발성 추론

## 3. 통합 이벤트 스키마 (제안)

```json
{
  "patient_id": "string",
  "timestamp": "ISO8601",
  "module": "posture | facial | pill",
  "event_type": "posture_alert | fall_detected | pain_spike | medication_check",
  "confidence": 0.0,
  "evidence": { "...모듈별 근거 데이터(keypoint, landmark, bbox 등)" },
  "requires_immediate_alert": true
}
```

모든 모듈이 이 스키마로 통일해 FastAPI에 POST하면, 챗봇 쪽 S 데이터와 합쳐 SOAP 리포트 조립이 쉬워진다.

## 4. 개발 우선순위 제안 (로컬 프로토타입까지)

| 순서 | 모듈 | 이유 |
|---|---|---|
| 1 | 자세/낙상 감지 | 사전학습 포즈 모델만으로 즉시 데모 가능, 학습 데이터 불필요 |
| 2 | 알약 인식 | YOLO 파인튜닝 필요하지만 공개 데이터셋으로 착수 가능 |
| 3 | 표정 분석 | 임상 데이터 확보가 가장 오래 걸림 — 1단계(랜드마크+규칙) 수준으로 축소해 병행 |
