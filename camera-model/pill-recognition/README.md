# 알약 인식 (복약 확인) — 김도현

복약 시간에 어르신이 카메라에 약을 비추면 지금 먹어야 하는 약이 맞는지 알려주는 모델. 이슈 #12.

## 전체 흐름

```
AI Hub 경구약제 이미지 (10종만) + 배경 합성 + COCO 일상 사진(알약 없음)
        ↓ 학습 (YOLO11n, 이 PC의 RTX 5060 Ti)
  ONNX 변환 → public/models/pill/ (pill_classifier.onnx + classes.json + model-metadata.json)
        ↓
웹 환자 화면: [복용했어요] → 카메라 카드가 커지며 알약 확인
  맞는 약 → [먹었어요] → /api/medication 기록 → 의료진 화면 "오늘 복약 현황"
```

- 학습 대상 10종 (`classes.json`, 순서 = 클래스 번호)
  - 시연 2종: 리리베아캡슐 50mg (K-045037), 타이레놀정 500mg (K-004378) — 시연 환자 다나카 하루코의 아침·저녁 약
  - 다른 약 8종: 색·모양이 다른 약 6종(레드리버 연질캡슐, 듀오락스, 퍼킨, 복합파자임, 토파제, 베스자임) +
    비슷한 흰 약 2종(무스판정 ≈ 타이레놀, 독립목클린캡슐 ≈ 리리베아) — 모델이 색만 보고 외우지 않고 모양·각인까지 보게
  - 전체 이미지(3.4TB)는 못 받으므로, 시연 약이 든 이미지 zip 2개(TS_3 93GB, VS_10 24GB) 안에서 8종을 골랐다
- 확신이 낮으면 "잘 모르겠어요" (10종 밖의 약 오인 방지), 같은 약이 약 1초 이어질 때만 판정
- 영상은 브라우저 안에서만 처리 (onnxruntime-web)

## 모델 없이 화면 확인하기

개발 서버에서 `http://localhost:3000/patient?pillDebug=1` → [복용했어요] → 알약 확인 패널 아래 개발용 버튼
(맞는 약 / 다른 약 / 애매함 / 여러 알 / 없음)으로 흐름을 확인할 수 있다. 배포 환경에서는 동작하지 않는다.

## 직접 사진 찍기

```bash
conda activate biohealth-camera
cd camera-model/pill-recognition
python capture_pills.py --drug pending:amlodipine
```

`own_photos/<약 코드>/`에 사진과 위치 정보(json)가 저장된다. 손이 나올 수 있어 레포에는 올리지 않는다(`.gitignore`).
촬영 팁은 `capture_pills.py` 맨 위 설명 참고.

## 모델 파일 (`public/models/pill/`)

| 파일 | 내용 |
|---|---|
| `pill_classifier.onnx` | 모델 (YOLO11n, 10.6MB) |
| `classes.json` | 클래스 번호 순서대로 약 코드·이름 |
| `model-metadata.json` | 모델 버전, 입력(1x3x640x640, RGB, /255, 회색 114 레터박스), 출력(1x14x8400), 클래스 순서, 기준값(검출 0.4 / 맞는 약 0.6·1초, 리리베아만 0.8 / 다른 약 0.9·3초), 날짜, 시험 성적 |

`train_pill.py --export-only runs/pill_v2/weights/best.pt`로 다시 만들 수 있다.
웹은 `NEXT_PUBLIC_PILL_MODEL_URL`(기본 `/models/pill/pill_classifier.onnx`)로 모델 위치를 바꿀 수 있고,
메타데이터는 모델과 같은 폴더의 `model-metadata.json`을 읽는다 (`NEXT_PUBLIC_PILL_MODEL_METADATA_URL`로 변경 가능).

## 가운데 네모만 보기 + 확대해서 다시 보기 (`lib/pill/zoom.ts`)

웹캠 첫 테스트에서 거의 모든 프레임이 "여러 알"로 판정됐다. 원인과 대응:
- 표정 카메라라 얼굴·옷·머리카락이 화면에 들어오는데, 알약만 있는 사진으로 학습해서 이를 색깔 약(레드리버·퍼킨정·복합파자임)으로 착각
  -> 환자 화면에 가운데 네모(짧은 변의 60%)를 그리고 모델에는 그 부분만 넣는다.
- 같은 알약에 크기가 다른 박스(전체와 반쪽)가 여러 개 -> IoU가 낮아도 작은 박스가 70% 이상 다른 박스 안에 있으면 같은 알약으로 합친다.
- 0.83 옆의 0.48 같은 약한 박스까지 알약으로 셈 -> 가장 확신 높은 박스의 75%보다 약한 박스는 세지 않는다.
원본 테스트 사진 1,116장에서는 바꾸기 전후 결과가 같다 (맞음 1,082 / 모름 34).

두 번째 웹캠 테스트에서 잠옷 무늬를 독립목클린캡슐 0.74~0.77로 꾸준히 착각했다. 잘못된 "다른 약" 기록이 의료진에게 가는 게
가장 비싼 실수라서 판정 기준을 나눴다 (`lib/pill/verdict.ts`):
- 맞는 약: 확신 0.6 이상이 1초 (그대로)
- 다른 약: 확신 0.8 이상이 2초. 못 미치면 "잘 모르겠어요"
- 확대 결과는 네모에서 본 약과 같거나 확신이 더 높을 때만 쓴다 (네모 리리베아 0.78 -> 확대 무스판정 0.62 같은 뒤집힘 방지)


학습 사진에서는 알약이 화면 폭의 25~30%를 차지하지만, 웹캠(1280x720)에서 손에 든 알약은 10% 안팎이라
640 입력으로 줄이면 각인이 뭉개진다 (특히 흰 바탕에 음각인 타이레놀).
그래서 네모 안에서 한 알을 찾았는데 작으면 그 주변(네모 안)을 잘라
알약이 30%를 차지하도록 키워서 한 번 더 판정하고, 확대한 쪽에서 한 알이 보이면 그 결과를 쓴다.

테스트 사진을 1280x720 단색 화면 안에 작게 넣어 흉내 낸 결과 (약마다 24장, 실제 웹캠 사진은 아님):

| 알약 크기 (화면 폭 대비) | 전체만 | 확대 재판정 |
|---|---|---|
| 약 10% | 맞음 215 / 다른 약 7 / 모름 18 | 맞음 214 / 다른 약 0 / 모름 26 |
| 약 7% | 맞음 192 / 다른 약 19 / 모름 29 | 맞음 217 / 다른 약 1 / 모름 22 |

약 7%일 때 타이레놀은 24장 중 6장이 무스판정으로 틀렸는데, 확대하면 24장 모두 맞았다.
개발 서버에서는 콘솔(Verbose 수준)에 1초마다 `[알약 인식] 네모 무스판정 0.70 -> 확대 타이레놀정 0.88` 식으로 찍힌다.

## v2: 알약 없는 배경 사진으로 재학습 (`add_backgrounds.py`)

v1은 AI Hub 알약 사진만 봐서 "이건 알약이 아니다"를 배운 적이 없었다. 그래서 웹캠에 함께 찍힌 잠옷 무늬·옷·얼굴을 알약으로 착각했다.
COCO val2017 일상 사진(사람·옷·실내)을 정사각형으로 잘라 "알약 없음"(빈 라벨)으로 학습 2,000 / 검증 200장을 넣었다.
따로 떼어 둔 500장으로 배경 오인식을 잰다. v1 가중치에서 이어서 20 epoch 학습했다 (약 2시간, 12 epoch이 가장 좋았음).

| 시험 (`test_report.json`) | v1 | v2 |
|---|---|---|
| mAP50 / mAP50-95 | 0.983 / 0.883 | 0.995 / 0.915 |
| 웹 기준 판정 정확도 (1,116장) | 96.95% | 98.39% |
| 다른 약으로 틀림 | 0% | 0% |
| 리리베아 맞음 | 55.6% | 83.3% |
| 배경 500장 중 알약 박스가 나옴 | **75.6%** | **1.2%** |
| 배경이 맞는 약 기준(0.6)을 넘음 | 54.8% | 0.6% |
| 배경이 다른 약 기준(0.8)을 넘음 | 9.2% | 0% |

알약이 화면 폭의 약 7%로 작게 보이는 상황을 흉내 내면, 가운데 네모 + 확대 재판정으로 1,116장 중 1,101장이 맞았다 (v2).

알려진 오인식: 리리베아와 독립목클린은 둘 다 글자 없는 흰 캡슐이라 뒷면끼리는 구분이 안 된다.
v2는 독립목클린 뒷면을 리리베아로 0.70~0.78 확신해서, 리리베아만 맞는 약 기준을 0.8로 올렸다
(`model-metadata.json` thresholds.classConfidence). 리리베아 진짜 사진은 앞면 0.89~0.92, 뒷면 대부분 0.8 이상이다.
기준을 넘지 못하면 "잘 모르겠어요" + 각인이 보이게 돌려 달라는 안내가 나온다.
작은 알약 시뮬레이션에서는 독립목클린 36장 중 1장이 여전히 다른 약으로 판정됐다.

## 흰 캡슐 각인 OCR (`lib/pill/capsuleOcr.ts`)

v2 웹캠 테스트(Safari, MacBook)에서 배경 착각은 거의 사라졌지만, 리리베아와 독립목클린은 글자 없는 면이 똑같아 모델이 헷갈린다.
또 "다른 약" 기준(0.8·2초)에 0.81~0.86이 가끔 닿아서 기준을 **0.9·3초**로 올렸다.

모델이 리리베아나 독립목클린으로 보는 상태가 1초 이어지면, 확대 사진에 tesseract.js를 **한 번만** 돌린다 (약을 내려놓으면 다시 읽을 수 있음).
- 전처리: 회색조 -> 평균보다 밝은 곳 = 캡슐 -> 긴 축을 수평으로 -> 줄마다 캡슐 양 끝 사이만 남김 -> 폭 800px -> 주변 밝기보다 어두운 곳만 검정
- 바로 / 180도 두 번 읽고, 글자 조각으로 정한다: PGN·DWB 등(거꾸로 읽힌 8MQ 등 포함) -> 리리베아, ACC·DLB·OLB 등 -> 독립목클린
- 각인으로 못 정하면 확대 사진과 함께 "캡슐에 DWB PGN 50 글자가 보이나요?" + [맞아요] / [아니에요]로 환자에게 묻는다

데이터셋 사진 144장(약마다 72장, 절반은 글자 없는 면)에서 웹과 같은 전처리로 잰 결과:

| | 각인으로 맞게 정함 | 잘못 정함 | 못 정함 (사람이 확인) |
|---|---|---|---|
| 리리베아 | 19 | 0 | 53 |
| 독립목클린 | 36 | 0 | 36 |

글자 조각 목록은 같은 사진들을 보고 정했으므로 실제 웹캠에서는 이보다 낮을 수 있다.
OCR 실행 파일과 영어 데이터는 처음 쓸 때 CDN(jsdelivr)에서 받고, 사진은 브라우저 밖으로 나가지 않는다.
개발 서버 콘솔에 `[알약 인식] 캡슐 각인 OCR: [...] -> 리리베아캡슐 50mg`처럼 찍힌다.
